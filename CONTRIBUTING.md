# Contributing

Thanks for helping improve `awesome-textmode`!

## Scope

This list is for resources that are directly useful to people exploring textmode culture in general.

Good fits include:

- Textmode libraries, plugins, and creative-coding frameworks.
- Editors, renderers, viewers, and playgrounds.
- Pixel, ANSI, PETSCII, and other textmode-friendly font resources.
- Scene archives, long-running groups, and historically important community hubs.
- Public apps, showcases, and companion tools with a clear textmode connection.

Usually not a fit:

- Generic creative-coding tools with no meaningful textmode relevance.
- Private, invite-only, unpublished, or placeholder projects.
- Low-effort forks, abandoned experiments, or duplicate entries.
- Marketing pages with no usable product, code, or documentation.

## Quality Bar

Please only suggest items that are genuinely worth recommending.

Each submission should be:

- Publicly accessible.
- Clearly relevant to textmode art, textmode tooling, or textmode culture.
- Documented enough for someone else to understand why it matters.
- Maintained, usable, or historically important in a way that is clearly called out.

## Entry Format

Use this format:

```md
- [Project Name](https://example.com)
  - Short objective description.
  - By [Author](https://example.com) - License.
```

For entries where author and license don't apply (e.g. community Discord servers), the description alone is fine.

Rules:

- Use the canonical project name.
- Prefer a repository link when the repository is the main public home.
- Use a product or documentation URL when that is the main public surface.
- Keep descriptions concise and factual.
- Start descriptions with an uppercase letter.
- End descriptions with a period.
- Link to the specific license when possible; otherwise note it in plain text (e.g. `Freeware`, `Public domain`).
- Always credit the author with a `By` line linking to their profile or homepage.

## Placement

- Add entries to the most relevant existing section.
- Keep entries alphabetized within a section.
- If you add a new section, also update the `Contents` list.
- Prefer the smallest correct change.

## Pull Requests

Before opening a pull request, make sure that:

- The item is not already listed.
- The link works and points to the intended destination.
- The description explains why the item is useful.
- The formatting matches the surrounding entries.

In your pull request description, include:

- What you added or changed.
- Why it belongs in `awesome-textmode`.
- Any context that helps with review, especially for newer or niche projects.
